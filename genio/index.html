Problem問題

  • A module maker wants Ubuntu 26.04 on its Genio 420 system-on-module and carrier. MediaTek supports Ubuntu up to 24.04 (as of 2026), and only on eMMC, which this module does not use.一家模組廠想在自家的 Genio 420 模組與載板上跑 Ubuntu 26.04。MediaTek 只支援到 24.04（2026 年時），而且只支援 eMMC，這塊模組用的不是 eMMC。
  • The product needs a camera, a time-sensitive network port and an AI demo, and the boards must be installed and restored by people without a serial cable.產品需要相機、時間敏感網路埠和一個 AI demo，而且板子要讓沒有 serial 線的人也能安裝與還原。

Solution解法

  • Keep the vendor boot chain and replace only kernel and rootfs. The kernel finds root by PARTLABEL, so a rebuilt Ubuntu rootfs boots without touching the bootloaders.保留原廠的開機鏈，只換 kernel 與 rootfs。kernel 用 PARTLABEL 找 root，所以重建的 Ubuntu rootfs 不用動 bootloader 就能開機。
  • Kernel 6.6.137 rebuilt from the IoT Yocto v26.0 tree plus one board layer. Device trees and overlays come out byte-identical to the vendor's.kernel 6.6.137 從 IoT Yocto v26.0 的原始碼樹加一層板層重建，產出的 device tree 與 overlay 和原廠位元組一致。
  • Install from the network or a USB stick. A Windows PC is the station: DHCP, TFTP, HTTP and one web page. Factory restore takes 100 s, the unified system 135 s.從網路或 USB 碟安裝。一台 Windows PC 當站台，提供 DHCP、TFTP、HTTP 和一個網頁。回復出廠 100 秒，裝統一版 135 秒。
  • An i.MX RT1180 as a DSA switch under Linux. A package applies one YAML of TSN settings at boot and shows the file next to the hardware state on a page.i.MX RT1180 在 Linux 下當 DSA 交換器。一個套件在開機時套用一份 TSN 設定 YAML，網頁上並列檔案內容與硬體現況。

Key screens主要畫面

Install station裝機站

  • A board plugged into the station NIC appears within 60 s of power-on, identified by its storage serial. One button installs the unified system; another restores the factory one.板子接上站台網卡後，上電 60 秒內就會出現，以儲存裝置序號識別。一個按鈕裝統一版，另一個回復出廠。
  • The job has five phases: assess, prepare, schedule, track, verify. Each is checkpointed per board, so a failed or cancelled job resumes where it stopped.作業分五個階段：assess、prepare、schedule、track、verify。每塊板各自存 checkpoint，失敗或取消的作業可以從停下的地方續跑。
  • The board does the install itself from RAM: U-Boot loads the installer over TFTP, the installer streams the rootfs over HTTP, verifies it and reboots.板子自己在 RAM 裡完成安裝：U-Boot 用 TFTP 載入安裝器，安裝器用 HTTP 串流 rootfs，驗證後重開。
  • The terminal shows the board's console, built from the job's serial log and the SSH journal. The CLI runs the same job code.終端機把作業的 serial log 與 SSH journal 合在一起，就是這塊板的 console。CLI 跑的是同一份作業碼。

tsn-manager

  • One YAML file describes the two external TSN ports and the 802.1AS clock. A service turns it into tc, ethtool and ptp4l calls at boot and on every save.一份 YAML 描述兩個對外 TSN 埠與 802.1AS 時鐘。服務在開機與每次存檔時，把它轉成 tc、ethtool、ptp4l 指令。
  • The left column is the file and can be edited; the right column is what the hardware is running, read every five seconds and never editable. Four lamps show switch, time lock, schedule and whether the two sides match.左欄是檔案，可以編輯；右欄是硬體正在跑的設定，每五秒讀一次，不能編輯。四盞燈顯示交換器、時間鎖定、排程，以及檔案與硬體是否一致。
  • A schedule applied from this page was checked with hardware timestamps on the far node.從這個頁面套用的排程，在對端用硬體時戳驗證過。
  • On a board without the switch the service installs and stays off, which is not an error.沒有交換器的板子，服務照裝但不啟動，不算錯誤。

Benchmark and NPU demos實測數字與 NPU demo

NPU 10.3 ms per SSD MobileNet v2 inference. STREAM read 18 GB/s on the CPU side, 15 GB/s from the GPU.GPU FP32 112 GFLOPS（clpeak）。對照的理論峰值 113 是用 Genio 520 頁面上同一顆 GPU 的 880 MHz 時脈推算，420 沒有公布時脈。glmark2 369 分。NPU 跑 SSD MobileNet v2 每次 10.3 ms。CPU 端 STREAM 讀取 18 GB/s，GPU 端 15 GB/s。

The sheet ends with a rule of thumb: GPU for compute-bound FP32 (2.1 times the CPU, measured), NPU for INT8 (by MediaTek's rated TOPS), CPU for small jobs.GPU 跑 SAXPY 只比單執行緒 NEON 的 CPU 快 1.3 倍，因為兩者都撞上同一道 DRAM 頻寬牆。表尾留了一條選型規則：算力型 FP32 給 GPU（實測 2.1 倍），INT8 給 NPU（依官方額定 TOPS），小工作留在 CPU。
  • A first version of this sheet used home-made metrics and a pure-Python baseline and overstated the GPU. It was redone with clpeak, glmark2, sysbench and neuronrt; that is the version shown, and the Mandelbrot render stays as a GLES functional check only. Measured on the earlier mixed system; the numbers set the plan.這張表的第一版用自製指標與純 Python 分母，高估了 GPU。後來改用 clpeak、glmark2、sysbench、neuronrt 重做，圖上是重做版，Mandelbrot 只當 GLES 功能驗證，不計入效能。在前期的混搭系統上量的，這些數字決定了後面的計畫。
  • Detection demo: SSD MobileNet v2 (COCO) on the NPU at 14 ms per frame inside the live USB-camera pipeline; the 10.3 ms on the sheet is the same model under neuronrt alone. The 19.8 fps camera is the bottleneck.偵測 demo：NPU 跑 SSD MobileNet v2（COCO），在即時 USB 相機管線裡每幀 14 ms；表上的 10.3 ms 是同一個模型只跑 neuronrt 的數字。瓶頸在 19.8 fps 的相機。
  • VLM demo: Qwen3VL-2B on the NPU answers questions about the live camera image and points at what it names. It ships as a package the customer installs and was verified on the board's DP display. The model package comes from MediaTek's model zoo; the kit does not redistribute it.VLM demo：NPU 上的 Qwen3VL-2B 回答即時相機畫面的問題，並指出它提到的東西在哪裡。做成客戶自行安裝的套件，在板子的 DP 螢幕上驗過。模型套件來自 MediaTek 的 model zoo，交付包不轉散布。

Latency probes use hardware timestamps on the receiving NIC.延遲探測用收端網卡的硬體時戳。

Results結果
802.1ASOffset in the tens of ns. Two-hop boundary clock under a line-rate flood: the far node stays within 32 ns, measured with independent hardware timestamps.offset 在幾十 ns。兩跳 boundary clock 在線速洪流下，對端偏差不超過 32 ns，用獨立的硬體時戳量得。
802.1QbvA 200 µs gate delays the class it closes by 208 µs at p99 and 243 µs at worst; a 500 µs gate by 513 and 548 µs. The express class stays at the sender's noise floor.關 200 µs 的閘門讓被關的 class 多等 208 µs（p99）、最差 243 µs；關 500 µs 則是 513 與 548 µs。優先 class 停在送端的雜訊底。
802.1QciPolice and gate counters match the configured rates within 3%, and the drop count equals the firmware's red count.police 與 gate 的計數與設定值差在 3% 以內，丟包數等於韌體的 red 計數。
802.1QbuPreemption verification SUCCEEDED, TX active, and time sync held during the test.搶占驗證 SUCCEEDED、TX active，測試期間時間同步沒有掉。
Install time安裝時間Factory restore went from 263 s to 100 s and the unified install from 492 s to 135 s, through faster hashing and compression, a smaller master image and no idle waits.回復出廠從 263 秒縮到 100 秒，裝統一版從 492 秒縮到 135 秒。手段是更快的雜湊與壓縮、更小的母版映像，以及不空等。
Decode解碼The hardware H.264 decoder held 3 frames on IP-camera streams whose SPS has no reorder depth, adding 107 ms of decode latency. A GStreamer element that writes the missing reorder depth into the SPS cuts it to 5 ms.IP camera 串流的 SPS 沒寫 reorder depth，硬體 H.264 解碼器就會囤 3 幀，解碼延遲 107 ms。一個把缺的 reorder depth 補進 SPS 的 GStreamer 元件，把延遲降到 5 ms。
Glass to glassGlass-to-glassGMSL3 camera to screen 127 ms at 1024 × 768, 60 fps, and 166 ms at 4K30, measured by a camera-to-display feedback loop with a time-code bar. The wait for vblank in kmssink was the bottleneck, not the display driver.GMSL3 相機到螢幕 127 ms（1024 × 768、60 fps），4K30 則是 166 ms，用相機拍螢幕的回饋迴路加時間碼直條量出來。瓶頸是 kmssink 等 vblank，不是顯示驅動。
Scheduling排程延遲cyclictest on the stock 6.6 kernel under a hackbench load: worst case 1.4 to 2.2 ms, RT patch not applied yet. This number is why EtherCAT master stays an open item.現行 6.6 kernel 在 hackbench 負載下跑 cyclictest，最差 1.4 到 2.2 ms，RT patch 還沒套。EtherCAT 主站還掛在未結項目，原因就是這個數字。

Decisions決定

Only kernel and rootfs are replaced只換 kernel 與 rootfs

  • Boot is a relay: BROM, BL2, BL31, OP-TEE, U-Boot, kernel, rootfs. The vendor's first five stay as shipped; kernel and rootfs are mine, with the vendor's modules and firmware copied in.開機像接力：BROM、BL2、BL31、OP-TEE、U-Boot、kernel、rootfs。原廠的前五棒照舊，kernel 與 rootfs 換成我的，原廠的模組與韌體搬進來。
  • The kernel partition has no backup copy, so it is dumped before every write.kernel 分割區沒有備援，每次寫入之前都先 dump 一份。

SD is for installing onlySD 只拿來安裝

  • U-Boot's MediaTek SD host never gets past ACMD41 on this board; ten hypotheses were tested and ruled out. The network and USB paths use the mature Synopsys and xHCI drivers and worked first time.這塊板上 U-Boot 的 MediaTek SD host 過不了 ACMD41，十個假設逐一實驗排除。網路與 USB 走成熟的 Synopsys 與 xHCI 驅動，一次就通。
  • Rule kept from it: a command listed in help is not a feature that works. fastboot is listed, but there is no USB gadget controller.從這件事留下的規則：help 列出的指令不代表功能真的能用。fastboot 有列出來，但板上沒有 USB gadget 控制器。

The driver cleans the switch on shutdown驅動在 shutdown 時清掉交換器狀態

  • The RT1180 switch keeps DSA tag rules, stream filters and gate lists across a warm reboot, and left in place they blocked U-Boot and the installer at the CPU port. shutdown and remove now release them and restore each port's PVID.RT1180 交換器的 DSA tag 規則、stream filter 與閘門清單會撐過熱重開機；留著不清，U-Boot 與安裝器就會被擋在 CPU port 外。shutdown 與 remove 現在會釋放它們，並還原每個埠的 PVID。
  • A hang traced to a PTP mutex that was never initialised, fixed together with the SPI command path and the firmware's command status reporting.一次卡死追到一把從未初始化的 PTP mutex，連同 SPI 命令路徑與韌體的命令狀態回報一起修掉。

A self-hosted runner installs real boards台架上的 runner 裝真板

  • Hosted CI runs the unit and API tests on every push. A self-hosted runner on the bench PC installs a real board whenever a new asset Release is published, and rebuilds the kernel on request.hosted CI 每次 push 跑單元與 API 測試。台架 PC 上的 self-hosted runner 在每次發布檔 Release 時裝一塊真板，也能按需求重編 kernel。
  • The runner is a service account with its own WSL distro, and setup, status and full removal are three scripts.runner 是一個獨立的服務帳號，配自己的 WSL distro。安裝、查狀態、完整拆除各是一支腳本。

Board evidence beats documents板上證據優先於文件

  • A dump or log from the board beats the datasheet, which beats the official docs, which beat a blog post.板上的 dump 與 log 優先於規格書，規格書優先於官方文件，官方文件優先於部落格文章。
  • The factory-restore runbook was replayed end to end before it was called done.回復出廠的 runbook 從頭到尾實走一次才算完成。

Delivery交付

  • Two repos: the working repo holds everything, including bench logs, and the deployment kit is synced from it commit by commit through a manifest, so the customer never sees a bench path.兩個 repo：工作 repo 放全部內容，含台架 log；交付包經 manifest 從它逐 commit 同步，客戶看不到任何台架路徑。
  • The kit holds the install station, the USB installer, the BSP build in Docker with the board layer, the RT1180 firmware and driver patches, tsn-manager, the VLM package, the decoder fix and three runbooks.交付包內容：裝機站、USB 安裝碟、Docker 內的 BSP 建置與板層、RT1180 韌體與驅動 patch、tsn-manager、VLM 套件、解碼修正，以及三份 runbook。
  • Large files are GitHub Release assets with a committed sha256 ledger; fetch-assets.py downloads 4.6 GB and verifies each file.大檔案放在 GitHub Release，配上已提交的 sha256 校驗清單；fetch-assets.py 下載 4.6 GB 後逐檔驗證。
  • LICENSES.md names every component, its license and its source. Vendor runtimes whose redistribution is not yet confirmed are marked as such.LICENSES.md 列出每個元件、授權與原始碼來源。原廠 runtime 轉散布權還沒確認的，照實標明。
  • A residue scan runs before each sync and refuses personal paths and names in the kit.每次同步前跑一次殘留掃描，交付包裡出現個人路徑或人名就擋下。

cd station && uv run station      # http://127.0.0.1:8080
