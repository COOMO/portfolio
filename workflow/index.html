The problem問題

  • A vague request gets code immediately, with the wrong assumptions baked in.要求講得模糊，程式碼馬上就來，連錯誤的假設一起寫進去。
  • "Fixed" often means it still breaks, plus a new side effect.「修好了」常常是一跑還是壞，還多一個副作用。
  • A green test suite is not a working feature. Instruments and tablets do not read test output.測試全綠不等於功能可用。儀器和平板不看測試結果。

Pin1

Git first先建 Git

  • First command in a new folder: git init.新資料夾第一個指令：git init。
  • Claude Code's checkpoint only undoes its own edits inside one session; it does not cover what you ran by hand, other machines, branches or review.Claude Code 的 checkpoint 只能倒回同一個 session 內它自己的改動，管不到你手動跑的、別台機器、分支和 review。
  • One branch per issue. Each commit maps to a ROADMAP step. Diffs are what gets reviewed.一個 issue 一條分支，一個 commit 對應一個 ROADMAP 步驟；review 看的是 diff。
Pin2

Three documents before code寫程式前的三份文件

The three documents三份文件
SPEC.md
  • Requirements in EARS form: WHEN, THEN, SHALL. No sentence a model can read two ways.需求用 EARS 格式：WHEN、THEN、SHALL。沒有一句模型能讀出兩種意思。
SDD.md
  • Architecture, data, error handling, acceptance. The model writes the happy path on its own; the other two sections are the point.架構、資料、錯誤處理、驗收。happy path 模型自己會寫；後兩項才是重點。
  • Written by interview: the model asks me one question at a time until it reaches what I had not thought of.用訪談的方式寫：模型一次問我一題，一直問到我沒想過的地方為止。
ROADMAP.md
  • Numbered steps, each small enough to finish and verify alone. Numbers never change: 12 splits into 12a and 12b. Dropped steps keep a placeholder and one line why.編號步驟，每步小到能獨立完成與驗證。編號永不改：12 要拆就是 12a、12b。不做的步驟留 placeholder 和一行原因。
  • benchpress today: 1,388 lines, 169 done, 102 open.benchpress 目前：1,388 行，169 項完成，102 項未做。
Pin3

A short CLAUDE.md一份精簡的 CLAUDE.md

  • Read at the start of every session. It tells the model to tick the ROADMAP box and update "Currently working on" after each step.每個 session 開頭都會讀。規定模型每完成一步就打勾 ROADMAP、更新「Currently working on」。
  • Under 200 lines. Test per line: if this line were gone, would the model make a mistake? If not, delete it.200 行以內。每一行問：拿掉這行模型會犯錯嗎？不會就刪。
  • Rules that earned a line in U3: every code path has a MockVisa story; outputs never auto-enable; watch CI to the end after every push.在 U3 裡值得一行的規則：每條程式路徑都有 MockVisa 版本；輸出絕不自動開啟；每次 push 盯 CI 到結束。
  • Rules in U2: write an operation_logs row for every mutation, no exceptions; never hardcode the shop name or a flavor.U2 的規則：每個變更都寫一列 operation_logs，沒有例外；店名和口味絕不寫死。
Pin4

Gates the model cannot talk its way past模型說不過去的關卡

The task loop used on U3. Dashed boxes are the gates.U3 使用的任務流程。虛線框是關卡。

1Open an issue開 issue
2Plan in plan mode, approveplan mode 規劃，核可
3Branch issue/N, build開 issue/N 分支，實作
4cargo check · fmt · clippy -D warnings · test
5Pull request with a lab-safety checklistPR 附實驗室安全檢查表
6Second-model review, gating第二個模型 review，有否決權
7Apply comments, stop. Run hardware by hand.套用意見後停下。手動跑實機。
8Squash merge, watch CI to the endsquash 合併，盯 CI 到結束
  • The pause at step 7 is deliberate: green mock tests do not prove the feature, the instrument does.第 7 步的停頓是故意的：mock 測試綠不代表功能可用，要儀器說了算。
  • Hardware tests are #[ignore] and need BENCHPRESS_HW=1. Acceptance per instrument is logged with firmware and commit.實機測試標 #[ignore]，要 BENCHPRESS_HW=1。每台儀器的驗收記韌體與 commit。
  • For U2 the gate was the counter: feedback came as phone photos of the tablet, and the next commit answered them.U2 的關卡是櫃台：回饋是用手機拍平板畫面的照片，下一個 commit 就回應它們。

Real prompts真實的 prompt

From the U3 project notes, unedited. Chinese as written; English alongside.取自 U3 的專案筆記，原文未修改，英文為對照翻譯。

The old flow is hard-coded. I want the new flow to be built by dragging, like blocks: combine commands from different instruments into a full test item, with waits and the like. Also allow for several GPIB or Ethernet interfaces sending commands and handling replies at the same time.舊的操作流程是寫死的, 希望新的操作流程可以藉由拖拉的方式, 像積木一樣組合不同儀器的 command 拼湊出完整的側項, 也可以設定等待時間之類的操作, 另外也要考慮若有多條 GPIB 或 ethernet 介面, 同時發送指令和處理的可能性Brief · became the block model and parallel lanes需求 · 成了積木模型與平行車道
Plan an Error Handler flow. It is a special state entered whenever an error occurs. It must filter errors and, by severity, either let them pass or handle them.請規劃新增一個 Error Handler 流程 這是當任何時候有錯誤發生時會進入的特殊狀態, 要可以過濾錯誤, 視不同等級的錯誤放行或錯誤處理Change request · became per-step Halt / Continue / Retry with severity修改需求 · 成了每步的 Halt / Continue / Retry 與錯誤分級
Code cleanliness matters.code cleanliness 很重要ROADMAP M9 · led to deleting 9 crates and 1,500 lines once templates replaced themROADMAP M9 · 模板上線後據此刪掉 9 個 crate、1,500 行

Why it matters為什麼重要

  • The value is in being forced to think the idea through before any code exists; the documents are the by-product.價值在於被迫在寫程式之前把想法想清楚；文件是順帶的產物。
  • A clear spec is implemented fast. A vague one produces something that looks right and is wrong, just as fast.規格清楚，實作很快。規格模糊，一樣快做出看起來對其實錯的東西。
  • The model does the typing. The gates, the hardware and the counter decide what ships.打字的是模型。決定什麼能出貨的是關卡、儀器和櫃台。
