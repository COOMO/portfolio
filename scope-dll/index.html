scope dll

A C++ DLL that puts an R&S RTB2000 oscilloscope into a third-party ATE. Two APIs: Soft AMR and FWF. Called from LabVIEW and C++. 把 R&S RTB2000 示波器整合進第三方 ATE 的 C++ DLL。兩組 API：Soft AMR 與 FWF。LabVIEW 與 C++ 都能呼叫。

Problem問題

  • A third-party ATE on a production line needed an oscilloscope inside its test routine. The integration point is a DLL call: the ATE calls one function per step and reads the files back.產線上有一台第三方 ATE，需要在測試流程裡用示波器。整合方式是 DLL 呼叫：ATE 每個步驟呼叫一個函式，結束後讀回產出的檔案。
  • Each board has dozens of pins. When a pin leaves its voltage window, the waveform itself has to be saved.一塊板有幾十支 pin。任何一支的電壓一超出上下限，就要把當時的波形留下來。
  • The scope's history buffer is finite, so a step with more triggers than it can hold loses the oldest waveforms before anyone reads them back.示波器的 history 緩衝區有限，一個測項觸發太多次，最舊的波形在讀回之前就被蓋掉了。

Solution解法

  • Soft AMR opens one session per pin with that pin's voltage window. The scope triggers on every excursion; the DLL keeps the segments, steps the trigger level toward the signal peak, and at the end dumps each violating segment with a screenshot.Soft AMR 為每支 pin 開一個 session，帶上它的電壓上下限。示波器對每次超限觸發，DLL 把這些 segment 留下來，把 trigger level 一步步往訊號峰值推，最後把違規的 segment 連同截圖一併倒出。
  • FWF captures up to four channels in sync from one trigger pin. Each pin's V/div comes from its limits, and the segments are grouped by function with a zoom view.FWF 用一支觸發 pin，同步擷取最多四個通道。每支 pin 的 V/div 由它的上下限算出，segment 依功能分組，另有 zoom 視圖。
  • Every run writes HTML, XLSX, CSV, a JSON summary and a log. The ATE reads the files; there is no GUI.每次執行產出 HTML、XLSX、CSV、JSON 摘要與 log。ATE 讀的是檔案，沒有 GUI。
  • One function per step: init, open, mark, dump, close. A new version never forces the ATE to change its calls.一個步驟對應一個函式：init、open、mark、dump、close。新版本不會逼 ATE 改既有的呼叫。

Key screens主要畫面

Zoom dumpZoom dump

  • Each segment can be dumped as a second image: the whole record on top, a zoom window below.每個 segment 可以多存一張圖：上半是整段紀錄，下半是放大視窗。
  • The zoom is centred on the segment's own peak, not on the trigger point. The peak is found with the scope's own search over the full record.zoom 以該 segment 自己的峰值為中心，而不是觸發點。峰值由示波器自己在完整紀錄上搜尋。
  • The trigger level shown is the level at capture time, not the latest one. The DLL records the level per segment and switches the display back before each shot.畫面上顯示的 trigger level 是擷取當時的值，不是最後一次設定。DLL 替每個 segment 記下當時的 level，截圖前先把顯示切回去。

History segmentsHistory segment

  • The scope runs with history on. Each excursion past the trigger level is one segment with its own time stamp.示波器開著 history 執行。每次越過 trigger level 就是一個 segment，各有自己的時戳。
  • amr_mark names the test step that is running, so each segment is attributed to the step that produced it and the report groups by step.amr_mark 標記目前在跑的測項，segment 歸到產生它的那個測項，報告也依測項分組。
  • The DLL detects overflow: when a step produces more segments than the history holds, the report says so instead of silently losing the oldest.DLL 會偵測滿溢：一個測項的 segment 多過 history 容量時，報告會寫明，而不是默默丟掉最舊的。

Sync capture同步擷取

  • fwf_open takes a list of pins: channel, name, V/div. The trigger pin arms a single acquisition; then the ATE runs the function.fwf_open 接收一串 pin 設定：通道、名稱、V/div。觸發 pin 先 arm 一次擷取，然後由 ATE 執行功能。
  • Each pin's V/div is either given explicitly or derived from that pin's limits.每支 pin 的 V/div 可以直接指定，也可以由該 pin 的上下限算出。
  • Segments are centred the same way in TIM:POS and ZOOM mode, so the overview and the zoom report line up.TIM:POS 與 ZOOM 兩種模式用同一套置中規則，所以全景與 zoom 報告對得起來。
  • A window with no trigger is not a failure; the DLL captures a blank snapshot and the report says no trigger.時間窗內沒有觸發不算失敗，DLL 照樣截一張空白畫面，報告寫明沒有觸發。

AMR reportAMR 報告

  • Totals, violations, pass rate, then one row per segment with its screenshots inline.總數、違規數、通過率，接著每個 segment 一列，截圖直接嵌在裡面。
  • A warning line records anything that changed during the run; in this one, an automatic vertical-scale change had cleared the scope's history.警示列記下執行途中發生的變動；這份報告裡是垂直刻度自動換檔，示波器的 history 因此被清掉。
  • The XLSX has a sheet per pin: Vp+, Vp-, notes, and how many times the trigger level was adjusted.XLSX 每支 pin 一張工作表，列出 Vp+、Vp-、備註，以及 trigger level 被調整過幾次。

FWF reportFWF 報告

  • One section per function, one row per pin group: the overview and each segment.每個功能一節，每組 pin 一列，放全景與各個 segment。
  • Measurements are optional, and the scope computes them.量測值可開可關，數值直接由示波器計算。
  • Reports are ordered by run, so a repeated function keeps its history.報告依執行順序排列，同一個功能重跑時前後紀錄都會保留。

API

// Soft AMR, one scope, many pins. Return 1 on success; amr_last_error() has the text.成功回 1；錯誤文字看 amr_last_error()。
amr_init("TCPIP::192.0.2.31::INSTR");            // once per session每個 session 一次

amr_open(channel, low, high, …);              // window, scale, time base, trigger, out dir上下限、刻度、時基、觸發、輸出目錄
amr_mark("P01_PowerUp", 0);                      // the ATE step startsATE 測項開始
// … the ATE runs its routineATE 跑它的流程 …
amr_step_trigger_level();                        // optional: chase the peak可選：追峰值
amr_dump_segments(…);                            // violating segments, screenshots違規 segment 與截圖

amr_open(channel + 1, …);                        // next pin; results accumulate下一支 pin，結果累積
// …
amr_generate_report();                           // HTML + XLSX + CSV + JSON
amr_close();

// FWF, four channels, one trigger四通道一觸發
fwf_init("TCPIP::192.0.2.31::INSTR");
fwf_open(pins, 4, …);                            // channel, name, V/div per pin每支 pin 的通道、名稱、V/div
fwf_start();  /* run the function跑功能 */  fwf_dump("OpenShort", …);
fwf_generate_html_report();  fwf_close();
  • Plain C ABI. LabVIEW calls it through Call Library Function nodes, and a VI per function ships with the DLL.純 C ABI。LabVIEW 透過 Call Library Function 節點呼叫，DLL 附每個函式對應的 VI。
  • Non-blocking flow for long steps: amr_has_new_trigger polls, fwf_start arms and returns.長測項用非阻塞流程：amr_has_new_trigger 輪詢，fwf_start arm 完就回來。
  • New behaviour arrives as a new parameter whose zero value is the old behaviour, so the ATE's existing calls keep working.新行為以新參數加入，傳 0 就是原本的行為，ATE 既有的呼叫不用改。
  • Every run writes a debug log of each SCPI exchange with timing; the firmware quirks below were found in those logs.每次執行都留一份 debug log，記錄每條 SCPI 往返與耗時，下面幾個韌體怪癖都是從這裡找出來的。
  • Release notes per version, in the ATE team's language, naming the log that triggered each fix.每個版本都有版本紀錄，用 ATE 團隊看得懂的話寫，並註明是哪份 log 引出哪個修正。

Decisions決定

Peak search runs on the scope峰值搜尋在示波器上做

  • Reading a full record back over the network takes seconds per segment, and reading it at display resolution misses narrow spikes. The scope's own search finds the peak in about a second and never moves the history index.把完整紀錄經網路讀回，每個 segment 要好幾秒；用顯示解析度讀回又會漏掉窄 spike。示波器自己的搜尋約一秒就找到峰值，而且不會動到 history index。

Trigger steps are monotonictrigger 步進只往一個方向

  • The earlier two-tier rule pulled the level back toward the measured peak and then out again, so when the scope's statistics froze on a narrow pulse the level oscillated forever. The steps are now monotonic, with a guard that widens the vertical scale after three rounds and, if that still fails, gives up and flags the pin in the report.舊的兩段式規則會把 level 先拉回量到的峰值再往外踩，示波器的統計一被窄脈波凍住，level 就永遠震盪。現在改成單調步進，加上一道防呆：連續三輪沒收斂就放大垂直刻度，再不行就放棄，並在報告上標記這支 pin。

Firmware quirks handled in code韌體怪癖在程式裡處理

  • On this scope's firmware, turning ZOOM on while stopped resets the history index to the newest segment. A zoom shot that showed a flat line where the main shot showed a waveform gave it away. The DLL now re-selects the segment after ZOOM ON.這台示波器的韌體在 STOP 狀態下打開 ZOOM，會把 history index 重設到最新的 segment。一張 zoom 圖只有平線、主圖卻有波形，就是這樣被抓到的。DLL 現在在 ZOOM ON 之後重新選回該 segment。
  • Trigger levels past the hardware limit and steps below the minimum resolution both used to stall the loop. Both are now clamped and logged.trigger level 超過硬體上下限，或步進小於最小解析度，以前都會讓迴圈卡住。現在兩者都會夾限並記進 log。

Fixes start from field logs修正從現場 log 開始

  • The ATE team sends the run folder: log, report, screenshots. Each fix in the release notes names the log and the pin that showed the problem, and the demo program then reproduces the case so the fix can be seen on the bench.ATE 團隊把執行資料夾寄來：log、報告、截圖。版本紀錄裡每個修正都註明是哪份 log、哪支 pin 出的問題，再用 demo 程式把那個情境重現，修正在台架上就看得到。
